## 2. 架构级优化

### 2.1 权限与数据边界

- 新增统一服务端访问策略，工作区、消息、任务、流程和知识文档不再依赖前端隐藏；
- boss/coach 全局可见；backbone 可见本人工作区和本部门项目；developer/staff 仅见成员工作区；
- 非成员访问敏感资源统一返回 404，避免泄露资源存在性；
- 知识密级落实为 L1/L2 全员、L3 同部门、L4 同部门骨干及管理层；
- 普通员工界面只保留“协作空间、任务中心、知识库”，默认直接进入协作空间；
- 开发者治理页不再出现无权访问的审计页签。

### 2.2 真实模型执行与可观测性

- 模型配置支持 Base URL、模型名、temperature、timeout、启停和连接测试；
- Kimi Coding 地址自动规范为 `/coding/v1`，温度默认 1，解决真实调用参数不兼容；
- 模型 Key 使用 AES-256-GCM 加密落库；
- 任务记录供应商、模型、执行模式、耗时和脱敏错误；
- `llm_calls` 留存调用成功/失败、耗时与回落原因；
- 模型失败仍保证业务可用，但界面明确提示模板回落，不再静默伪装成真实模型结果；
- 工作区数字员工全部离线时，登记“待处理”任务并提示负责人和可选在线员工。

### 2.3 登录与 IM

- 会话 12 小时过期，退出立即撤销；
- OAuth state 不再携带人员 ID，改为不可预测、限时、一次性凭证；
- 真实 IM 登录按外部账号查既有绑定，不信任前端 person_id；
- 回调以 2 分钟一次性短码换平台会话，token 不进入 URL；
- 登录页可免平台 token 获取钉钉/飞书授权 URL并轮询结果；
- 二维码由同源后端生成，断公网或二维码公共 CDN 不可用时仍可显示；
- 模型 Key 和 IM Secret 自动从老库明文迁移为密文。

### 2.4 业务闭环

- 新增人级 AI 成效：创建任务、通过产出、未闭环任务、最近活跃；
- 激励完成“申报→评定/驳回→确认发放”闭环，并实时校验年度资金池余量；
- 算力报销三级分权保持通过；
- 审计支持 CSV 导出并防 Excel 公式注入；
- 422 参数错误统一中文化；
- 方案 28 部门、232 场景容量落库：81 个已定义场景 + 151 个透明标记的待部门提报储备位；
- Skill、数字员工、MCP、场景输入增加角色与枚举/关联校验。

### 2.5 交付与离线能力

- Tailwind、ECharts、二维码脚本全部本地化；
- 启动脚本自动检查 Python 和依赖，缺失时按 `requirements.txt` 安装；
- 增加健康探针、安全响应头、仅本机 CORS；
- 前端静态资源增加版本缓存键；
- 手机端协作空间改为上下布局，修复横向溢出；
- 依赖、启动、权限、API 和 PRD 进度文档同步更新。

## 5. 客户现场前置条件

以下不是系统代码缺陷，但必须在现场明确：

1. 钉钉管理员确认应用回调地址与客户访问域名完全一致，并用一个已绑定员工账号完成首次真实扫码；
2. 若启用 Multica 真实外部 Agent，需提供实际 workspace/Agent UUID；当前 API 契约和 bridge 已通过，真实 CLI 环境尚未提供；
3. 151 个“待部门提报场景”是方案容量位，不应向客户描述为已完成业务需求；需由各部门补充名称、数据口径、责任人和验收标准；
4. 若客户不是在本机 `127.0.0.1:8000` 访问，需在部署前配置正式反向代理、HTTPS 与钉钉回调域名。

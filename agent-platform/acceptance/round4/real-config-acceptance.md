## 二、真实模型验证

### 1. 阿里云模型

- 从用户提供的 CSV 中只在内存读取兼容端点和密钥，未写入报告或 Git。
- `/models` 返回 200，共发现 231 个可用模型；最小对话调用返回 200。
- 将 `qwen3.7-flash` 设为平台默认模型后，平台生成链路成功：任务 #11 约 14.9 秒进入“待审核”，交付物 465 字，未发现“待补充/模板示例”等占位标记。
- 当前模型配置 API 只能修改 `api_key/default_model/enabled`，不能修改 `base_url`。本次只能绕过产品界面直接更新运行时数据库，普通管理员无法独立完成真实端点接入。
- 阿里云官方文档说明兼容端点可能是工作空间专属地址；同时 Coding/Token 类套餐面向交互式编码工具，正式作为企业后台服务前应确认授权范围：[阿里云 Model Studio Base URL 文档](https://help.aliyun.com/en/model-studio/base-url)。

### 2. Kimi Coding

- 用户给出的地址是 Anthropic 风格根地址；当前平台使用 OpenAI 兼容协议，实调采用官方 OpenAI 兼容地址 `https://api.kimi.com/coding/v1`。
- 鉴权及模型列表成功，可见 `kimi-for-coding` 等模型；使用服务端要求的 `temperature=1` 时最小调用返回 200。
- 平台执行引擎在 `app/engine.py` 固定发送 `temperature=0.4`，Kimi 返回 400；异常在同文件中被统一捕获并返回 `None`，前台没有“模型调用失败”的明确提示，用户会误以为模板结果来自真实模型。
- 判定：Kimi 配置可保存，但**不能通过当前平台真实出件**。需要让温度可配置/按供应商适配，并记录调用错误、供应商、模型、耗时和是否回退。
- Kimi 官方说明该 Coding API 主要供编码 Agent/工具使用，生产业务集成应先确认套餐与调用场景：[Kimi Code API 文档](https://www.kimi.com/code/docs/en/)。

## 三、钉钉授权验证

- 从人才管理系统的默认配置读取并解密 AppKey/AppSecret，随后通过平台配置 API 写入；接口响应仅显示“已配置”。
- 平台生成的钉钉 OAuth 地址包含 `code/openid/consent/state` 等必要参数；直接访问返回钉钉登录页 200，未出现 AppKey 或回调地址即时错误。
- 浏览器中点击“绑定钉钉”后，二维码组件加载失败。根因是登录页从 `cdn.jsdelivr.net` 动态加载二维码脚本，传统制造企业内网/受限网络下不可依赖公共 CDN。
- 未完成真人扫码、授权确认、回调换 token、用户绑定落库、退出重登五步闭环，因此不能宣称钉钉已经正式可用。
- 安全差异：人才系统使用 AES-256-GCM 加密保存 AppSecret；本平台的 `model_providers.api_key` 和 `auth_providers.app_secret` 均为 SQLite 明文字段。生产上线前必须改为环境密钥/密钥服务或至少应用层加密。

## 四、普通员工完整旅程

### 成功路径：员工 #42，工作区 #4

1. 员工登录成功。
2. 在本人工作区输入自然语言要求，无需写 Prompt 模板。
3. 系统派发 1 个数字员工任务，约 14.9 秒生成交付物。
4. 任务 #11 状态为“待审核”；`creator_id=42`，`reviewer_id=2`，职责分离正确。
5. 交付物非空、无明显模板占位符。
6. 普通员工尝试审核返回 403；任务状态未改变。

### 失败路径：徐露璐，工作区 #2

1. 本人只有一个工作区，唯一数字员工状态为“已下线”。
2. 在 Agent 区发送任务后，消息保存成功且接口返回 200，但未派发任何任务。
3. 产品没有解释“数字员工已下线”，也没有推荐可用员工、通知管理员或创建待处理需求。

这意味着平台能让“部分员工在部分工作区”使用，但尚未达到“每个普通员工可直接使用”。

## 五、阻塞与整改优先级

### P0：上线前必须修复

1. **工作区越权读取**：所有工作区查询、消息、任务、文件、执行链路 API 必须按成员关系服务端授权；非成员返回 403/404。前端隐藏不能代替后端鉴权。
2. **普通员工可用性兜底**：数字员工下线时不能静默成功。应返回明确状态并提供“提交待处理需求/联系负责人/选择在线员工”动作。
3. **凭证安全**：模型 Key、钉钉 Secret 不得明文落库；日志、审计、异常响应不得携带密钥。

### P1：试点前必须修复

1. 模型配置增加 Base URL、协议类型、温度、超时、测试连接；供应商配置错误时禁止静默回退。
2. 交付物记录真实供应商、模型、调用状态、耗时、回退原因，供审核人追溯。
3. 二维码库本地化打包，完成真人钉钉 OAuth 全链路回归。
4. 普通员工首页只显示与本人有关的工作区和操作；隐藏模型、治理、组织配置等非本职模块。
5. 为关键旅程增加自动化：成员权限矩阵、下线 Agent、模型 4xx/5xx/超时、OAuth state 防重放。

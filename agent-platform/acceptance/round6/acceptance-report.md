## 1. 数字员工连续模型互动

根因：R5 以前 Agent 执行区只把消息转换成一次性交付任务，模型提示词不携带历史对话、
项目流程、知识库和业务数据；私聊打磨则是固定模板，无法持续深化项目。

修复：

- Agent 执行区升级为 Agent 协作区，默认“连续对话深化”，可切换“正式派活交付”；
- 连续对话以所选数字员工身份调用其绑定模型；
- 模型上下文注入数字员工职责/技能/场景动作、最近 14 条对话、项目任务与后续流程、
  当前人员有权访问的知识分块，以及默认制造业务数据相关明细；
- 模型未配置或调用失败时明确显示原因，不使用模板冒充模型回答；
- 正式派活继续生成交付物并进入人工审核；旧 API 未传模式时仍默认派活，保持兼容；
- `llm_calls` 对聊天调用记录供应商、模型、状态、耗时和脱敏错误。

真实联调：

| 项目 | 结果 |
|---|---|
| 数字员工 | 外贸跟单数字员工 |
| 模型 | 通义千问 `qwen3.7-flash` |
| 第一轮回复 | 成功，23,572 ms，结合订单数据与项目流程给出交付风险和首步动作 |
| 第二轮追问 | 成功，21,672 ms，继承上一轮上下文，拆解今天/本周/本月动作与人工输入缺口 |
| 页面可追溯 | 显示“真实模型回复：qwen / qwen3.7-flash · 耗时” |

## 2. Excel 知识库解析

修复：

- 上传白名单新增 `.xlsx/.xls`；
- 解析全部非空工作表，空表自动跳过；
- 列名清洗与去重，数值列推断为 INTEGER/REAL，日期规范化为 ISO 文本；
- 每个工作表写入独立 SQLite 表，并写 `sheet_index` 元数据；
- 每个工作表同时生成 UTF-8 BOM CSV；
- 生成 Markdown 摘要及每 50 行一个知识 chunk，供数字员工召回；
- 文档详情可查看工作表、SQL 表名、行列数，并可在线预览、下载 SQLite/CSV；
- 启动脚本自动检查并安装 `openpyxl`、`xlrd`。

真实上传证据：

| 工作表 | SQL 表 | 行数 | 列数 |
|---|---|---:|---:|
| OrderDetails | `sheet_OrderDetails` | 2 | 6 |
| QualityRecords | `sheet_QualityRecords` | 1 | 5 |

- `converted_format=sqlite+csv`；
- SQLite 内含 `sheet_index` 与两个业务表；
- SQL 在线预览通过；
- SQLite 下载 HTTP 200，文件 20,480 bytes；
- CSV 下载 HTTP 200；
- 客户演示文档已保留为“制造业务数据验收样例”（L1）。

## 3. 默认 1000 条业务数据

- 新增 `business_records` 表；
- 固定生成 `DEMO-0001` 至 `DEMO-1000`；
- 销售订单、生产报工、质量检验、库存流水、售后工单各 200 条；
- 包含日期、部门、客户、产品、数量、金额、状态、指标与扩展明细；
- 每次启动执行幂等补齐：重复启动不增加，缺失任意默认编号会自动补回；
- 普通员工知识库首页直接看到 1,000 条及五类分布，可打开最近 50 条明细；
- API 支持业务类型、关键词和分页查询；
- 数字员工连续对话自动召回相关业务明细。
